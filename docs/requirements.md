## 1. 项目概述

### 1.1 项目名称
维策 · 决策导向的预测性维护智能体 PrognosOps

### 1.2 项目定位
不看预测准不准,只看这次检修值不值。

### 1.3 项目目标
构建面向设备运维工程师的预测性维护决策智能体。系统接收设备传感器数据,估计剩余使用寿命(RUL)的概率分布,并基于成本与质量双目标给出最优维修窗口建议,回答"这次检修值不值"的核心问题。

### 1.4 目标用户
- **设备运维工程师**:负责制定设备维修计划,需要量化的决策依据。
- **预测性维护研究者**:需要验证决策导向维护策略的效果。

### 1.5 核心价值主张
传统预测性维护聚焦"还能用多久"(预测精度);PrognosOps 聚焦"现在修还是等一等"(决策价值),将 RUL 不确定性、维修成本、运行风险统一纳入期望成本/质量框架。

## 3. 功能需求

### FR-01 CSV 数据上传
**用户故事**:作为运维工程师,我想上传 NASA C-MAPSS FD001 格式的 CSV 数据,以便系统分析我的设备。

**验收标准**:
1. 用户可通过网页选择并上传 CSV 文件;
2. 系统识别 FD001 标准格式(26 列:unit, cycle, op_setting1~3, s1~s21,无表头或含表头均可);
3. 上传成功后返回数据概览:设备单元数、各单元周期数、传感器列清单;
4. 格式不符时返回明确的错误说明(缺列、列数不符、非数值数据);
5. 单文件大小限制 50 MB;
6. 上传后数据存入后端会话,不落盘明文。

### FR-02 内置演示数据
**用户故事**:作为运维工程师,我想使用内置演示数据快速体验,以便了解系统能力。

**验收标准**:
1. 提供一键加载内置演示数据按钮;
2. 演示数据为 NASA C-MAPSS FD001 训练集的截取子集(至少 20 台设备完整生命周期);
3. 加载后与上传数据走完全相同的分析流程;
4. 演示数据来源在界面上明确标注。

### FR-03 数据质量检查
**用户故事**:作为运维工程师,我想查看数据质量报告,以便确认数据可信。

**验收标准**:
1. 检查项:缺失值比例、常量传感器(方差为零)、周期数不足 30 的单元、非数值异常、重复行;
2. 对 14 个选定传感器(s2,s3,s4,s7,s8,s9,s11,s12,s13,s14,s15,s17,s20,s21)单独标注质量状态;
3. 质量报告以结构化 JSON 返回,前端以表格+标注展示;
4. 存在严重质量问题(缺失>20% 或无常量过滤后有效传感器<14)时,给出警告但允许继续;
5. 质量检查由后端计算,前端仅展示。

### FR-04 特征提取(420 维)
**用户故事**:作为运维工程师,我想系统从原始传感器数据中提取特征,以便后续 RUL 估计。

**验收标准**:
1. 对选定单元,取最近 30 个周期的 14 个传感器读数;
2. 拼接为 420 维特征向量(30 周期 × 14 传感器);
3. 周期数不足 30 时,用最早可用周期前向填充(工程假设,见设计文档);
4. 特征提取前后端各保存一份,供 RUL 模块使用;
5. 特征向量维度必须严格等于 420,否则报错。

### FR-05 RUL 分布估计(Weibull)
**用户故事**:作为运维工程师,我想看到设备 RUL 的 Weibull 分布参数,以便了解寿命不确定性。

**验收标准**:
1. 后端基于 420 维特征估计 Weibull 分布参数 lambda(尺度)和 k(形状);
2. 估计方法:k 近邻检索 + 极大似然拟合(工程假设,见设计文档);
3. 返回 lambda、k 及拟合优度指标;
4. lambda > 0,k > 0,不满足时返回错误;
5. 该计算完全由后端 Python 数值模块完成,大模型不得参与。

### FR-06 离散 RUL 概率(H=150)
**用户故事**:作为运维工程师,我想看到离散化的 RUL 概率分布,以便用于决策计算。

**验收标准**:
1. 将 Weibull 分布离散化为 P(RUL = h),h = 0, 1, ..., 150;
2. 归一化保证 ΣP(h) = 1(在 [0,150] 上截断归一);
3. 返回 151 维概率向量及累计概率;
4. 概率值全部由后端计算;
5. 前端以柱状图展示分布。

### FR-07 维修决策策略(四种)
**用户故事**:作为运维工程师,我想看到 ETO-C、IEO-C、ETO-Q、IEO-Q 四种策略的决策结果,以便对比选择。

**验收标准**:
1. 对每种策略,在维修窗口集合 Z 中选出最优窗口 z*;
2. 返回各策略的:最优窗口、期望成本/质量、各窗口的期望值曲线;
3. 四种策略定义见设计文档(含工程假设);
4. 策略计算完全由后端 Python 数值模块完成;
5. 前端以表格+曲线对比展示四种策略。

### FR-08 维修窗口选择
**用户故事**:作为运维工程师,我想系统在 Z={0,5,10,...,125} 中推荐维修窗口,以便安排检修计划。

**验收标准**:
1. 候选窗口集合 Z = {0, 5, 10, 15, ..., 125},共 26 个;
2. 每种策略输出各自最优窗口 z* ∈ Z;
3. z=0 表示建议立即维修;
4. 输出各窗口期望成本/质量的完整曲线,供工程师参考;
5. 窗口推荐由后端计算。

### FR-09 成本参数调整
**用户故事**:作为运维工程师,我想调整 cp、cc、cm、cd、alpha 参数,以便匹配实际成本结构。

**验收标准**:
1. 支持调整:cp(预防性维修成本)、cc(故障后维修成本)、cm(每周期监测成本)、cd(每周期退化损失成本)、alpha(折现因子);
2. 参数通过前端表单或自然语言修改;
3. 参数修改后,后端重新计算所有策略结果;
4. 参数校验:cp>0, cc>0, cm≥0, cd≥0, 0<alpha≤1,且 cc≥cp(否则警告);
5. 提供合理默认值(见设计文档)。

### FR-10 离线回测
**用户故事**:作为运维工程师,我想运行离线回测,以便验证策略在历史数据上的表现。

**验收标准**:
1. 对含真实故障标签的数据(如 FD001 训练集),在多个历史时点模拟决策;
2. 计算真实 regret:所选窗口的真实成本 − 完美信息下最优成本;
3. 返回各策略的 regret 统计(均值、中位数、分布);
4. **在线样本无真实 RUL 标签时,regret 字段必须返回 null**;
5. 论文实验结果不得硬编码为项目结果,回测必须真实计算。

### FR-11 自然语言参数修改
**用户故事**:作为运维工程师,我想用自然语言修改参数,以便快速调整配置。

**验收标准**:
1. 用户输入自然语言(如"把故障成本改成 8000,折现因子设为 0.95");
2. 大模型仅负责解析意图为结构化参数变更指令;
3. 参数变更由后端校验并应用,返回更新后的参数与重算结果;
4. 大模型不得直接修改数值,必须经后端校验;
5. 解析失败时返回澄清提示。

### FR-12 结果导出
**用户故事**:作为运维工程师,我想导出分析结果,以便归档和分享。

**验收标准**:
1. 支持导出 JSON(完整结构化结果);
2. 支持导出 CSV(策略对比表 + RUL 概率表);
3. 支持导出文本报告(含自然语言解释的可读报告);
4. 导出内容由后端生成,确保数值一致性;
5. 前端提供下载按钮。

### FR-13 自然语言决策解释
**用户故事**:作为运维工程师,我想获得决策结果的自然语言解释,以便向团队汇报。

**验收标准**:
1. 后端将计算结果(概率、成本、窗口、策略)作为上下文传给大模型;
2. 大模型基于上下文生成解释文本,说明为何推荐该窗口;
3. 解释中引用的数值必须来自后端计算结果,大模型不得编造;
4. 大模型调用失败时,降级为后端模板化解释;
5. 解释文本在前端展示并包含在导出报告中。

### FR-14 网页预览与云部署
**用户故事**:作为运维工程师,我想在浏览器预览和云端使用系统,以便随时随地访问。

**验收标准**:
1. 前端页面支持 JoyCode 浏览器直接预览(UI 壳 + 演示模式);
2. 完整功能通过启动后端服务获得;
3. 支持容器化云部署(JD DevCloud),端口 8080;
4. 部署后可通过公网地址访问;
5. 部署配置不暴露 API Key。

## 5. 约束与限制

1. 第一版仅支持 NASA C-MAPSS FD001 数据集;
2. 仅支持单台设备、单故障模式分析;
3. 窗口长度固定 30 周期,传感器固定 14 个,特征固定 420 维;
4. RUL 离散上限固定 H=150;
5. 维修窗口固定 Z={0,5,...,125};
6. V1 不包含模型训练,采用 k 近邻基线方法(工程假设,见设计文档);
7. 论文实验结果不得硬编码为当前项目结果。

## 6. 当前版本明确不支持的功能

- 多设备并行分析与设备群管理;
- 多故障模式识别与隔离;
- FD001 以外的数据集(FD002/FD003/FD004、自定义传感器集);
- 实时数据流接入(仅支持 CSV 批量上传);
- 备件库存与维修资源约束;
- 知识检索(RAG)与工单系统(CMMS)对接;
- 在线 regret 计算(无真实标签场景);
- 多用户权限管理与持久化数据库;
- 模型在线训练与增量学习。
